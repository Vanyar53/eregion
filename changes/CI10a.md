### Changed
- **The release gate measures every mutant without the work done twice** (CI10a, #580; `docs/design/preuves.md`, « Chaque mutant mesuré, sans le travail en double » ; `docs/operations.md`, « La porte de release »). Every mutant is still measured at every release, on the tree published, at 500 sequences; none is taken off, and CI6e's known survivors hold. The CI9 study measured where the gate's 42 runner hours went.
  - **One round where no chance plays.** A second round draws new seeds for Hypothesis only. A target keeps its rounds when one of its files imports Hypothesis (the invariant machines, the property tests), races (`tests/unit/test_locks.py`, `tests/unit/test_exercise.py`), cannot be read, or when its mutant is `TIMING`; any other target has one round (`rounds_of`). A row says its rounds (`1/1`), a shard's `--json` too (`mutant_rounds`, `mutant_targets`).
  - **The CD's mutants on the tests that catch them.** `python scripts/mutation_check.py --narrow FILE` runs each mutant whose target is FILE whole once without `-x`, and keeps its two fastest catchers as its target when they catch it in every round — else the whole file (`scripts/mutants/narrowed.json`). An entry applies only while its lot still targets that whole file; `scripts/mutant_anchors.py` says an entry that no longer applies or names a test its file lost. M1014 keeps its target.
  - **`--skip-machine-baseline`**: a shard runs no invariant machine unmutated, and says how many targets lost theirs — the gate's `invariants` job runs the whole suite at 2 000 sequences on the same tree. The rest of a target still runs unmutated. The Monday measure and a local run do not pass it (`tests/unit/test_mutation_shards.py` holds `mutants.yml` to it).
  - **`--machines`** measures only the mutants whose target runs an invariant machine (a file defining a `RuleBasedStateMachine`); `--total DIR --machines` judges those only, and refuses a shard measured otherwise. Without it, nothing changes. The control set keeps its own.
  - **One pool** for a shard's unmutated runs and its mutants, the heaviest first; the unmutated runs in a copy of their own, so nothing they write reaches a mutant's copy. An unmutated run that fails still makes the shard no measure.
  - `--update-durations` takes each measure as this tree runs it: scaled to today's rounds, and dropped when it was made on another target than today's (a narrowed CD mutant waits for the gate's next measure). `scripts/mutants/durations.json` refreshed from the gate's three runs of 05/11, their unmutated runs included.
  - The fake `docker` of `tests/unit/test_host_cd.py` starts with `python -S`: it needs the standard library only, and the file starts it about 4 300 times.
  - Tests: `tests/unit/test_mutation_shards.py`, `tests/unit/test_mutant_anchors.py`. Mutants M4170–M4189 (`scripts/mutants/CI10a.py`).
