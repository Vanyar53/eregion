### Changed
- **A faster CI: macOS off the pull requests, 200 invariant sequences there, a replaced run cancelled** (CI5, #512; `docs/operations.md`, « La CI, plus rapide »). Three pull requests pushing together queued their runs up to 15 minutes, and the macOS job, required, was often never acquired by a runner — the sessions' App cannot re-run it.
  - **macOS** (`tests (macOS, case-insensitive file system)`) runs on a push to `main` and every night (`schedule`; the night of `ci.yml` is its alone: a red audit would turn `main`'s commit red, and H0's CD refuses such a release). Its red on `main` — or its cancel: a timeout or a runner never acquired says `cancelled` — opens the issue « CI : les tests macOS sont rouges sur main », or comments the one this workflow opened (`--author app/github-actions`): job `macos-red`, `issues: write` to it alone, never on a pull request, no checkout nor action. A macOS red or cancelled on a release's commit makes H0's CD refuse to deploy it: Jonathan re-runs the job (the App cannot) before publishing.
  - **The invariants**: 200 sequences on a pull request, 500 on a push to `main`, 10 000 at night (`invariants.yml`, unchanged).
  - **`concurrency`** on CI, Images and Components: a new push on a pull request cancels the run it replaces; on `main`, at night and in a merge queue each run is its own group, never cancelled nor held pending.
  - **Components** is not run on a pull request of prose alone (`paths-ignore`: `**/*.md`, `docs/**`, `changes/**`, `LICENSE`); its checks are not required. Images keeps its own first step, which already skips the build.
