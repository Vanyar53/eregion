### Added
- **A release gate: the strongest measure on the tree a release publishes** (CI6, #514; Jonathan's decision of 04/11; `docs/operations.md`, « La porte de release »; `docs/sessions.md`, « Le cycle d'une release »). A version's pull request ran only a pull request's CI; nothing measured the published commit in full, and a commit newer than the last night could ship unmeasured.
  - **`.github/workflows/release-gate.yml`**: every test with 2 000 sequences per invariant machine (Linux), the whole mutation at 500 sequences and two rounds, control set included, ci.yml's macOS job and its Terraform tests, word for word. A last job, « release gate », waits for all of them and is green only if each one that blocks is: a cancelled or skipped job counts as red. **macOS informs, never blocks** (Jonathan's decision of 04/11, H1c, #518: only the required checks block — H0 runs Linux, and a runner GitHub never gives, as for the 0.5.4's commit, must never hold a release back): its job continues on error, and its outcome, with each job's result and role, is said in the run's summary. Every job bounded, `contents: read` and nothing else, every action pinned by commit, each job checking out the pull request's head exactly (never GitHub's merge commit).
  - **When**: on the version's pull request (`chore/release-X.Y.Z`, this repository's own; a pull request that changes `pyproject.toml` starts the workflow, any other one skips every job), so a red is seen before the merge; or by a dispatch on main. A new push cancels the run it replaces: one battery per tree.
  - **`make release-draft` refuses** until the gate's last run on a commit whose tree (`^{tree}`) is origin/main's is complete and green: a squash-merge changes the commit, not the tree, when nothing else merged in between. Otherwise it says which run, its state and its link, or that none measured this tree and how to dispatch it on main. No flag, no variable passes over it; `DRY_RUN=1` shows the check. Read by one `gh api` GET of the workflow's runs — the sessions' App reads it by its *Actions: read* (measured, 04/11). `make release` says, in its output and in the pull request's body, that the gate runs there and must be green before the merge.
  - **The mutation in shards** (`scripts/mutation_check.py --shard K/N --json`, then `--total`): one runner cannot measure 2 633 mutants (the Monday run, at 1 000 sequences, was cancelled at its 180 min bound on 02/11 before its first mutant). Each shard takes whole targets, in pieces of eight at most; the unmutated runs go in parallel; `--total` refuses a shard missing, twice, measured at another budget, or a mutant of the tree not measured exactly once, and holds the count to mutants.yml's `min_caught`. The control set is said, never held to a count.
  - Tests: `tests/unit/test_release.py` (refused without a gate, red, cancelled, skipped, running, on another tree, another pull request's, a fork's or one into another branch than main, unreadable, said nothing; accepted on a squash of the same tree and after a dispatch; the last started run decides, a run re-run included; no flag, no variable), `tests/unit/test_workflows.py` (the trigger, the permissions, the bounds, the shards, the last job run against `needs`), `tests/unit/test_mutation_shards.py`. Mutants M3590–M3605 (`scripts/mutants/CI6.py`).
