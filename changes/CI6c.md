### Fixed
- **`make release-draft` counts the version's pull request's gate once it is merged** (CI6c, #541; `docs/operations.md`, « La porte de release »). On the 0.5.5 (05/11), the gate was green on the version's pull request (run 41997986094), on origin/main's very tree, and `release-draft` refused it all the same: a `pull_request` run counted only if its `pull_requests` named a base `main`, and GitHub empties that list once the pull request is merged — `release-draft` always runs after the merge, so only a dispatch on `main` could ever pass.
  - The base is now read by every pull request of the run's head, closed ones included (`GET repos/{owner}/{repo}/pulls?head={owner}:<branch>&state=all&per_page=100`, the App's *Pull requests* read): measured on 05/11, `chore/release-0.5.5` gives #537, merged into `main`; `chore/release-0.4.10` gives #405, merged, and #385, closed unmerged. A commit's pulls (`…/commits/{sha}/pulls`) were not enough: they leave out a pull request closed unmerged (#385's head gives `[]`), so a pull request from the same head into another branch, closed before the version's merged, would have gone unseen (the review of CI6c).
  - Every pull request of the head must come from that branch of this repository and go into `main` of this repository, one of them with the run's commit for head, and none may ever have changed its base: each one's events (`GET repos/{owner}/{repo}/issues/{n}/events?per_page=100`) hold no `base_ref_changed` (measured on #353), `automatic_base_change_*` nor `base_ref_deleted`. Any base the run still names goes into `main` too.
  - The guards hold: the run comes from this repository's `chore/release-…` head, its branch and commit checked before they go into a path; a pull request into another branch, or none with the run's commit, passes the run over (said; an older run on the tree may decide). A read that fails, an answer that does not read, a full page (100 or more), a pull request without a number, a base changed refuses at once, and says it — never passed over for an older run. The tree is compared; nothing passes over the gate. One read per head and per pull request.
  - Tests: `tests/unit/test_release.py` (a merged pull request into `main` counts, its run naming none; an open one too; into another branch, merged or open, passed over; one closed unmerged into another branch from the same head, on the run's commit or an older one, refused; a base changed, on any pull request of the head, refused; a failed, unreadable or full-page read refused and said, never an older dispatch deciding; an empty answer passes the run over; another head's or a fork's pull request in the answer refused; a base of another repository, a commit no pull request's head, the run and the head's pulls disagreeing; one read per head; a commit or a branch GitHub would not give never read; a pull request without a number; the allow-list: the second and third `gh api`, GETs of a head's pull requests and of a pull request's events, and nothing else). Mutants M3770–M3784 (`scripts/mutants/CI6c.py`).
