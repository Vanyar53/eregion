### Fixed
- **The console marks each detection of the return channel signed or refused, as the injectors read it** (CON-S, #534; `docs/design/console.md`, « Les détections du canal retour »). `GET /api/channel/detections/<run_id>` judged nothing: the Runs view showed every blob of the channel as « delivered to the run », those SEC21's injectors refuse too. Each one is now judged by `watch_key.detection_refusal` with the key pinned on the console (`EREGION_WATCH_KEY`, never a key read in the channel): `signed` by the pinned key, for this run, under its signal's name, or `refused` with the run's own reason. Without a key pinned, or a value that is no key, the route says so with SEC19's gesture, and every detection is refused: none is shown as verified. The refused ones shown are `MAX_REFUSED` (20) at most, all counted (`refused`, `refused_shown`); a signed one is always shown. `injector.js` writes `SIGNED` only when the key is pinned and the server said signed, the reason and the fingerprint escaped (#254), no inline script (#257). The console's service already receives the watch's public key from SEC19, and gets no new right.
  - Tests: `tests/unit/test_console_signed_detections.py`; mutants M3750–M3759 (`scripts/mutants/CON-S.py`).
