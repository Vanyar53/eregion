### Changed
- **H0's CD holds a release only on the checks the rule of `main` requires, and on the image it pulls: a runner GitHub never gave no longer holds it** (H1c, #518; `infra/glorfindel-host/README.md`, « Le CD de H0 », point 2; `docs/sessions.md`, « Les règles du dépôt »). On 04/11 the 0.5.4's commit had every check green but macOS, cancelled for want of a runner: the CD refused any red or cancelled check, whatever it was, and would have refused it. Jonathan's decision, the same day.
  - **What holds**: the five checks `main` requires — `lint + tests (py3.11)`, `lint + tests (py3.12)`, `terraform test (mock providers)`, `image (annatar)`, `image (glorfindel)` — and `publish (glorfindel)`, the image the CD pulls (CI3). Red, cancelled or timed out: refused, said with the mention, as before. Still running: waited for. Absent: waited for an hour, each with its own count, then refused.
  - **What is only said**: every other check (macOS, the components, the compose profiles, `dependency advisories`, `publish (annatar)`…). Red or cancelled, `#deploy` says it in orange, without the mention, once per tag and per check; still running, it delays nothing. A check's name is compared whole: `lint + tests (py3.12) beta` never passes for a required one. What `#deploy` says of a name loses any URL, address or host name first (‹url›, ‹hôte›), then keeps letters, digits and `+ , . ( ) -` only — no `:` nor `/`, so no link Discord would make (SEC6).
  - **What counts for a check that holds**: GitHub Actions' runs only (`app.slug` = `github-actions`, read on `main`'s commits): another app's run named as a required job, green, never fills an absent one; red or still running, it holds all the same. Two runs of one name: a red one refuses, one still running waits. Completed without a green conclusion (none, or one the agent does not know): refused, never taken for green. Every page of the check runs is read.
  - **Where the list lives**: `REQUIRED_CHECKS`, a constant of the installed agent, never read from the repository nor from the release; a test keeps it equal to the list of `docs/sessions.md`, which now holds the five (macOS was taken off the rule of `main` on 04/11).
  - **The dry run** (`make glorfindel-host-cd-check`) shows both groups, each check with its state, also when the release runs already; the journal writes them at every pass.
  - **Before publishing the release that carries this**: `make glorfindel-host-cd-install`, from a checkout of `main` that has H1c — the CD's agent never replaces itself, and the one installed before still refuses a red or cancelled macOS.
  - Tests: `tests/unit/test_host_cd.py` (macOS cancelled, failed, never started or queued while the required ones are green: deployed, the red said once; each holding check red, cancelled or timed out: refused; each required one absent: waited an hour, then refused; one still running: waited for; a check not required still running: no delay; a red one said once per tag; neighbouring names; a name with a mention, a link, a bare URL, a host or Markdown; a holding check completed without a conclusion or with an unknown one; one name run twice; another app's runs; a required one only on the second page; the list equal to `docs/sessions.md`; the dry run). Mutants M3610–M3619 and M3640–M3645 (`scripts/mutants/H1c.py`), all caught; M1007, M1666 and M1696 re-anchored.
