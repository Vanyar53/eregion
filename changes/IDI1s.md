### Security
- **Orodruin's Graph guarantee is strict even undeclared: a directory role makes the contract passive, `EREGION_TENANT_ID` set or not** (IDI1s, #559 ; `docs/design/orodruin-contract.md`, « IDI1 »). Measured on 05/11 by Jonathan, the first `make orodruin-check` after v0.5.6 was `armed` with no `graph` note: the token of Orodruin's managed identity carries no `wids` outside `APP_DEFAULT_WIDS`, so the hypothesis holds and the list stays that value alone. A `wids` outside it is now `graph_directory_role`, passive, where it was only said without the declaration. The declaration decides two things only: an app role in the token (undeclared, any is `graph_undeclared_right`) and a Graph token that cannot be had — passive declared, only said undeclared, since an Orodruin without a Graph right must not fall and having no token is no privilege. Mutants M4225–M4229, M4240; M3941 (IDI1), whose code is gone, is retired. Microsoft does not document the `wids` value of a principal without a role: changed on their side, the contract turns passive (closed). Undeclared, a passing failure of the Graph token alone at startup leaves Orodruin armed without its `roles` and `wids` seen — bounded: a failing IMDS fails the ARM read too, the identity guard then refuses every identity, and no injector uses a token that cannot be had.
  - Tests: `tests/unit/test_orodruin.py -k graph`.
