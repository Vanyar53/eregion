### Added
- **Three more attack/detection pairs on VM: cron persistence, a Unix shell, Linux log clearing** (VM3, #548; `docs/azure.md`, « VM3 : trois paires de plus » ; `docs/operations.md`, « Les règles auditd de VM3 »). T1053.003, T1059.004 and T1070.002 move from `planned` to `implemented` in `technique_catalog.yaml`, each a pair. Red: a pinned Atomic Red Team test (`engine: atomic`, same vendored provenance as T1136.001 — repo, commit `9f6a1eab…`, sha256 in `annatar/atomics/PIN`), with a scenario in `annatar/scenarios/azure/` (steady-state probes prove the effect and the return to the initial state), played only from Orodruin on an enrolled target. The tests chosen run on Ubuntu with no outbound dependency: cron « Replace crontab » (435057fb), « Create and Execute Bash Shell Script » (7e7ac3ed) and « Overwrite Linux Log » (d304b2dc). Two are destructive — bench only, refused in production by the inscription (`safe_target: sandbox_disposable`): T1070.002 overwrites a log, T1053.003 replaces root's whole crontab and restores it from a predictable `/tmp` path, so its probes refuse a start where `/tmp/notevil` or `/tmp/persistevil` exist; the upstream cleanup leaves both, and the scenario's own revert removes them after it, which the after-probe verifies. Blue: three shipped rules that read telemetry Glorfindel already reads — `t1053-003-cron-crontab-replace` (Syslog facility cron), `t1070-002-log-tamper` and `t1059-004-shell-from-world-writable` (auditd via Syslog facility local6) — each with a threshold in its query and tested against realistic benign noise that must never fire (apt's cron, logrotate, unattended-upgrades; for `log_tamper` rsyslog's `rs:main Q:Reg` thread, sshd on wtmp/btmp/lastlog, useradd, waagent and the extensions under `/var/log/azure/`). `log_tamper` judges the writer by `exe` and the paths it touched, never by `comm`; the two auditd rules keep each record bounded and carry no free text of their own, so a writer's name never characterizes a card (useradd is no `account_creation` there). The coverage matrix (C1) shows them.
  - Tests: `tests/unit/test_vm3_pairs.py`; mutants M3840–M3859 and M3930–M3939 (`scripts/mutants/VM3.py`).
- **`engine_args` on an experiment: overrides for a vendored atomic's input arguments, held and vouched for by the catalog** (VM3, #548; `annatar/engines/atomic.py`, `schemas/experiment.schema.json`, `schemas/technique_catalog.schema.json`). So a pinned test runs faithfully without editing the vendored file — the shell test's ping goes to the loopback (no egress), the log overwrite to a disposable path (the cleanup restores it). The adapter refuses a key the test does not declare and a value outside `[A-Za-z0-9._/:-]` (nothing a shell would read otherwise); the parser refuses `engine_args` that are no mapping; `catalog_destructive` compares them to the catalog entry's — others make the run unknown, so destructive, never in production (SEC5, V-19). The campaign synthesizer resolves and writes the entry's own.
- **`revert` on an atomic experiment: what the upstream cleanup leaves, removed after it** (VM3, #548; `annatar/engines/atomic.py` `revert_commands`, `annatar/runner/engine.py`, both schemas). The E1 `revert` field now runs for `engine: atomic`: after the test's own cleanup, and only once it ran (a failed cleanup may still need those files), before the after-probes. One action, `remove_files`: paths, their `#{var}` filled, each a plain path inside `/tmp/` or `/var/tmp/`, sent as `rm -f --`. Anything else is refused before the contract is armed; the revert counts in the call cap; a failed or skipped revert is never a clean run, and the recovery hint gives it after the cleanup. Like `engine_args`, the catalog decides: a revert other than the entry's makes the run unknown, so destructive. T1053.003 uses it to remove `/tmp/notevil` and `/tmp/persistevil`; the vendored file is untouched.

### Changed
- **The auditd human-root reading (AUD1) stays the default for every T1059.004 rule, with one explicit exemption** (VM3, #548; `glorfindel/auditd.py`, `EXEMPT_RULES`). T1059.004 now carries a second shipped rule, `t1059-004-shell-from-world-writable`, whose rows (a Run Command exec, auid unset) are not of the human-root form: it alone, by name, is read as it comes. Every other rule of the technique — a client's under any name included — keeps settle, the fold and the rule window, and what is not of the human-root form stays an unreadable card (fail closed). An audit event row without a `SyslogMessage` of its own is told apart by its `AuditEvent` (`_row_identity`): two events of the same instant stay two.
- **Proposed telemetry, off by default** (VM3, #548; `infra/terraform/`). The cron facility is added to the bench DCR behind `cron_logs_enabled` (default false, `monitoring.tf`). The auditd rules the two auditd pairs read (`shell_exec`, `log_tamper`) are a script, `infra/terraform/scripts/vm3_auditd.sh`, laid on a bench VM by Run Command — not Terraform: Azure allows one CustomScript extension per VM, which AUD1 holds.
