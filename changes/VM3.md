### Added
- **Three more attack/detection pairs on VM: cron persistence, a Unix shell, Linux log clearing** (VM3, #548; `docs/azure.md`, « VM3 : trois paires de plus » ; `docs/operations.md`, « Les règles auditd de VM3 »). T1053.003, T1059.004 and T1070.002 move from `planned` to `implemented` in `technique_catalog.yaml`, each a pair. Red: a pinned Atomic Red Team test (`engine: atomic`, same vendored provenance as T1136.001 — repo, commit `9f6a1eab…`, sha256 in `annatar/atomics/PIN`), with a scenario in `annatar/scenarios/azure/` (steady-state probes prove the effect and the return to the initial state), played only from Orodruin on an enrolled target. The tests chosen run on Ubuntu with no outbound dependency: cron « Replace crontab » (435057fb), « Create and Execute Bash Shell Script » (7e7ac3ed) and « Overwrite Linux Log » (d304b2dc). T1070.002 is destructive — bench only, refused in production by the inscription (`safe_target: sandbox_disposable`). Blue: three shipped rules that read telemetry Glorfindel already reads — `t1053-003-cron-crontab-replace` (Syslog facility cron), `t1070-002-log-tamper` and `t1059-004-shell-from-world-writable` (auditd via Syslog facility local6) — each with a threshold in its query and tested against the known benign noise (apt's cron, logrotate, unattended-upgrades) that must never fire. The coverage matrix (C1) shows them.
  - Tests: `tests/unit/test_vm3_pairs.py` (the atomics resolve on Linux with cleanup and no egress, the rules fire on realistic lines and not on benign noise, the engine passes the overrides, the T1059.004 shell rule is read apart from the auditd human-root pipeline); mutants M3840–M3859 (`scripts/mutants/VM3.py`).
- **`engine_args` on an experiment: overrides for a vendored atomic's input arguments** (VM3, #548; `schemas/experiment.schema.json`, `schemas/technique_catalog.schema.json`). So a pinned test runs faithfully without editing the vendored file — the shell test's ping goes to the loopback (no egress), the log overwrite to a disposable path (the cleanup restores it). `annatar/runner/parser.py` carries it, `annatar/runner/engine.py` fills the test's `input_arguments` over its upstream defaults.

### Changed
- **The auditd human-root reading (AUD1) stays scoped to its one rule** (VM3, #548; `glorfindel/auditd.py`). T1059.004 now carries a second shipped rule (`t1059-004-shell-from-world-writable`), whose rows are not of the human-root form. The poller applies `settle`, the fold and the rule window only to `auditd.RULE` (`auditd-sensitive-root-command`, or a client rule replacing it under that name); another T1059.004 rule's rows pass through as read.
- **Proposed telemetry, off by default** (VM3, #548; `infra/terraform/`). The cron facility is added to the bench DCR behind `cron_logs_enabled` (default false, `monitoring.tf`). The auditd rules the two auditd pairs read (`shell_exec`, `log_tamper`) are in `infra/terraform/scripts/vm3_auditd.sh` with the variable `vm3_auditd_enabled` (default false); not wired to an extension — Azure allows one CustomScript extension per VM, which AUD1 holds — so enabling them is a manual bench gesture.
