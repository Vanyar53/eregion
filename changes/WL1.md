### Added
- **The bench's client layer sets bree's scheduled maintenance aside from `sudo-privilege-escalation`, and nothing else** (WL1, #595; `docs/glorfindel.md`, « La maintenance programmée de bree »). The cron of H0's pre-observation workload (`infra/terraform/scripts/workload.sh`: `nginx -t`, `systemctl reload nginx`, `journalctl --vacuum-time=14d` as `celebrimbor`, without a terminal) made a card every morning, judged `wrong` (Jonathan's decision, 06/11). `infra/glorfindel-host/client_rules.bench.yaml` holds the shipped rule copied as it is, plus one exclusion: bree alone (its host name and its resource), the account `celebrimbor`, no `TTY=`, nothing between `USER=root` and `COMMAND=`, these three commands with exactly these arguments. Another command, other arguments, another account, a terminal, another VM: a card, as before. The shipped base is unchanged.
  - Tests: `tests/unit/test_bench_routine.py` (forged lines in sudo's and the agent's forms); mutants M4265–M4269, one per property.
- **A client rule copied from a shipped one is set aside once the shipped rule changed, and the shipped rule runs** (WL1). The copy carries `base_sha256`, the fingerprint of the whole base rule it was taken from (`base_rule_sha256`: canonical JSON, keys sorted, UTF-8 — any field, not the query alone); at load, before the layers merge, a copy whose shipped rule changed is set aside and the shipped rule loads in its place — more cards, never fewer. It is said as drift (`DetectionConfig.drifted`, a note, in red in the watch banner and under `glorfindel rules`). A copy whose base rule is gone keeps running, and is said. A malformed fingerprint skips the copy (said) and the shipped rule loads. Mutants M4300–M4304. In the repository, the bench's copy is held to the base by its test: the pull request that changes the base fails until the copy is redone.
- **`make glorfindel-host-client-rules`: the bench's rules merged into H0's client layer** (WL1; `infra/glorfindel-host/README.md`, « La couche du client du banc »). H0's `~/.glorfindel/client_rules.yaml` is read by ssh, each rule added or replaced by its name (rules approved on H0 stay), read back as the watch will (`infra/glorfindel-host/host_client_rules.py`: nothing sent for a rule the watch would skip, a stale copy, or an unreadable layer), put in place under the layer's lock only if it did not change since it was read, then the watch restarts and `glorfindel rules` is shown. Jonathan's gesture, once a release with WL1 is deployed.
  - Tests: `tests/unit/test_host_client_rules.py` (the recipe against a fake H0).
